## 2026-09-10 — LLM не выбирает законы из памяти

**Контекст:** стандартный подход — «спросить у LLM, какая норма применима».

**Решение:** LLM **только переписывает текст**. Закон подставляет **код** из фиксированного списка.

**Причины:**
- LLM галлюцинирует: придумывает несуществующие номера статей
- Мы это видели: ФЗ «О полиции» как норма о тишине (ошибка)
- Hard-check + фиксированный список норм = детерминированно

**Для модуля 2:** 3 федеральные нормы захардкожены в `app.py`.
**Для модуля 3:** закон читается из `region/data/noise_laws.db` по региону.

## 2026-09-10 — База 85 регионов: YandexGPT Pro + host: фильтр

**Контекст:** 85 регионов, у каждого свой закон о тишине.

**Решение:** собрать базу через Yandex Search API + YandexGPT Pro с оператором `host:`.

**Причины:**
- `site:...OR site:...` не работает в Yandex Search API v2
- `host:... | host:... | host:...` — **работает**
- Официальные домены: `pravo.gov.ru`, `publication.pravo.gov.ru`, `docs.cntd.ru`, `base.garant.ru`, `consultant.ru`
- 81 из 85 регионов найдены автоматически
- 12 регионов захардкожены вручную (Крым, Севастополь, Татарстан, СПб и др.)

**Стоимость:** ~380 ₽ (из гранта).

**Версии базы (все сохранены в noise_laws.db):**
- `v1-minimal` — первый прогон (много ошибок)
- `v2-alice-pro` — неудачная попытка через Alice
- `v3-host-filtered` — Alice Pro + host: фильтр (6/10)
- `v4-pro-host-filtered` — **финальная** (81/85)
- `v3-hardcoded` — **приоритетная** для 12 регионов

## 2026-09-10 — Определение региона: гибрид regex + embeddings

**Контекст:** нужно понять регион из адреса пользователя («г. Москва, ул. Ленина, 15» → «Москва»).

**Решение:** два уровня.
1. **Regex** (26 паттернов на 85 регионов) — быстро, <1 мс
2. **Embeddings** (Yandex Text Embeddings, 85 векторов) — fallback

**Причины для embeddings:**
- Ловит нестандартные формулировки («посёлок Химки, рядом с Москвой»)
- Понимает опечатки

**Двойной фильтр для embeddings (иначе ложные срабатывания):**
- Скор топ-1 > **0.35**
- Разрыв топ-1 / топ-2 > **0.02**
- Без разрыва «ул. Ленина, дом 5» → случайный регион

**Обогащение городов:** у каждого региона список 2–18 крупных городов. Без этого «Химки» не находились (скор 0.33). С обогащением — 0.42. ✓

**Почему не Search Index AI Studio:** у объекта `SearchIndex` в SDK `yandex-ai-studio-sdk` нет метода `.search()`. Отказались, используем embeddings напрямую.

## 2026-09-10 — PDF: fpdf2 вместо reportlab

**Контекст:** первая версия PDF была на reportlab.

**Решение:** перешли на fpdf2.

**Причины:**
- reportlab кладёт шрифт без корректного ToUnicode CMap → текст из PDF **не копируется** (мусор при выделении)
- fpdf2 встраивает шрифт правильно → копипаст работает
- Побочный баг fpdf2: после `multi_cell(align="R")` курсор X остаётся справа → следующая ячейка падает. Решение: обёртка `_mc()`, сбрасывающая X на левый край.

## 2026-09-10 — Склонение ФИО: pymorphy3

**Контекст:** нужно склонять «Иванов Иван Иванович» → «Иванова Ивана Ивановича».

**Попытка 1:** библиотека `petrovich` 2.0.1 — **не работает**. Метод `last_name` отсутствует, все case возвращают исходное слово.

**Решение:** `pymorphy3`.

**Причины:**
- Работает стабильно
- Род определяется по отчеству: `-ович/-евич` → мужской, `-овна/-евна` → женский
- Явные теги частей речи: `Surn` (фамилия), `Name` (имя), `Patr` (отчество)
- Fallback на исходное слово, если не смог склонить

**Тесты:** 11/11.

## 2026-09-11 — Форма сохраняет данные при ошибке

**Контекст:** тестеры жаловались — заполнил описание, ошибся в телефоне, всё пропало.

## 2026-09-11 — Confidence / UNKNOWN (этап 4)

**Контекст:** hard-check уже умеет отличать vague-описание от нормального,
но показывал просто «Документ не составлен» без объяснения что не так.

**Решение:** ввести два новых понятия — pre-check отчёт и документ-заблокирован.

- `PreCheckReport` — три списка: `known`, `missing_critical`, `missing_optional`
- Каждый модуль имеет свой `run_*_pre_checks()`

**Причины:**
- Доверие: пользователь видит что система поняла и чего не хватает
- Меньше фрустрации: вместо «составьте заново» — конкретные подсказки

**Что считаем критичным:**

## 2026-09-11 — Версионность (этап 6)

**Контекст:** PDF-документы генерируются по шаблонам и правилам,
которые со временем меняются. Через год невозможно понять,
по какой версии сгенерирован конкретный PDF.

**Решение:** три поля версий в каждом документе.

- `engine_version` — какой движок (uk-01, noise-01, consumer-defect-01)
- `rules_date` — версия правил (формат 2026.09 — год.месяц)
- `template_version` — версия шаблона (1.0, 1.1...)

Где отображаются:
1. В **PDF** — серая строчка внизу, 8pt, цвет #787878
2. В **карточке дела** `/case/...` — блок «Версия документа»
3. В **БД** — сохраняются в таблице `cases` при создании

**Правило обновления версий:**
- `engine_version` — меняется при изменении логики модуля
- `rules_date` — меняется при обновлении норм (раз в квартал)
- `template_version` — меняется при правке PDF-шаблона
## 2026-09-11 — Legal Trace (этап 5)

**Контекст:** пользователь получает PDF, но не понимает, почему
система выбрала именно эту норму. Юридически это важно —
норма должна быть объяснима.

**Решение:** цепочка «Факт → Квалификация → Норма → Источник».

Где показываем:
1. В карточке дела `/case/...` — блок «Как система пришла к норме»
2. В DNA — сохраняется в поле `trace` как JSON
3. В PDF — пока не показываем (место ограничено, добавим позже)

**Почему в карточке, а не в PDF:**
- PDF — короткий документ, там нет места для объяснений
- Карточка — цифровое дело, может содержать метаданные
- Пользователь может зайти и посмотреть в любой момент

**Что кладётся в trace:**
- `fact` — что сказал пользователь (обрезано до 120 символов)
- `qualification` — юридическая квалификация (из словаря модуля)
- `norms` — список применимых норм
- `source` — URL источника (для модуля 3 — из БД, для модуля 2 — федеральные)
