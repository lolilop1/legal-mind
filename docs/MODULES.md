# Legal Mind — Modules

## Модуль 2 — Жалоба в УК

**Что делает:** жалоба в управляющую компанию на ненадлежащее
содержание общего имущества.

**Кому адресована:** управляющая компания.

**Правовые нормы (универсальные, федеральные):**
1. Статья 161 Жилищного кодекса РФ — ответственность УК
2. Постановление Правительства РФ от 13.08.2006 № 491
3. Постановление Госстроя РФ от 27.09.2003 № 170

**Типовые случаи:**
- Не убирают подъезд
- Холодные батареи
- Не работает лифт
- Не чистят снег
- Течёт крыша
- Сломан домофон

**Hard-check (modules/uk/hardchecks.py):**
- Emergency → STOP (газ, пожар, искрит проводка, трещина в несущей)
- Слишком коротко (<10 символов) → STOP
- Нет букв (только эмодзи/цифры) → STOP
- Слишком общее описание → STOP
- Жалоба на соседей → STOP
- Нет адреса → STOP

**Pre-check (modules/uk/pre_checks.py):**
- Объект проблемы — критично
- Дата начала — опционально

**Entity check:** проверяет сохранение существенных фактов —
дети, инвалиды, посторонние, номера квартир.

**Файлы:**
- modules/uk/hardchecks.py
- modules/uk/pre_checks.py
- modules/uk/entity_check.py
- modules/uk/pdf.py

**Статус:** работает. 12/12 API-кейсов, 62/62 офлайн-тестов.

## Модуль 3 — Жалоба на шум

**Что делает:** заявление участковому уполномоченному полиции
о нарушении тишины.

**Кому адресовано:** участковый уполномоченный полиции.

**Правовые нормы:** региональные (85 субъектов РФ).
База в region/data/noise_laws.db.

**Как определяется регион:**
1. Regex по адресу (26 паттернов) — быстро
2. Embeddings (85 векторов) — fallback
3. Если регион не найден — нейтральная формулировка

**Типовые случаи:**
- Громкая музыка по ночам
- Ремонт сверху
- Крики, скандалы
- Лай собаки
- Топот, вечеринки

**Hard-check (modules/noise/hardchecks.py):**
- Emergency → STOP (угрозы жизни, нападение, нож)
- Слишком коротко → STOP
- Нет букв → STOP
- Не про шум → STOP
- Не ясно, кто шумит → STOP
- Нет адреса → STOP

**Pre-check (modules/noise/pre_checks.py):**
- Вид шума — критично (музыка, ремонт, крики, лай)
- Источник шума — критично (сосед сверху, из кв. N, за стеной)
- Время суток — опционально
- Регион — опционально

**Файлы:**
- modules/noise/hardchecks.py
- modules/noise/pre_checks.py
- modules/noise/pdf.py
- region/extractor.py
- region/regex.py
- region/embeddings.py
- region/db_client.py
- region/data/noise_laws.db
- region/data/embeddings.json

**Статус:** работает. 12/12 API-кейсов, 19/19 офлайн-тестов,
регионы 26/26.

## Модуль 1 — Потребитель

**Что будет делать:** претензия по защите прав потребителей.

**Кому адресована:** продавец / маркетплейс.

**Правовые нормы:** ЗоЗПП (федеральный).

**Подмодули (по приоритету от людей):**

Подмодуль              | Статья    | Что                  | Приоритет
-----------------------|-----------|----------------------|----------
A. Товар с браком      | ст. 18    | Товар сломался       | 1
B. Возврат 14 дней     | ст. 25    | Не подошло           | 2
C. Маркетплейс         | ст. 26.1  | Ozon, WB, Авито      | 3
D. Услуга              | ст. 29    | Ремонт, курсы        | 4 (отложен)

**Архитектура:** один движок + 4 конфига.

- modules/consumer/engine.py
- modules/consumer/prompts.py
- modules/consumer/pdf.py
- modules/consumer/hardchecks.py
- modules/consumer/pre_checks.py
- modules/consumer/configs/defect.py
- modules/consumer/configs/return14.py
- modules/consumer/configs/marketplace.py
- modules/consumer/configs/service.py

**Сигнал от людей:** 95% обращений — про потребителя.

**Статус:** ✅ работает.

**Сценарии (авто-детект по тексту):**
- defect (ст. 18) — товар сломан/брак
- return14 (ст. 25) — товар не подошёл за 14 дней
- marketplace (ст. 26.1) — Ozon, WB, Яндекс.Маркет, Авито
- service (ст. 29) — ремонт, курсы, юруслуги, доставка

**Архитектура:** один движок (engine.py) + 4 конфига (configs/*.py).

**Номер заказа для маркетплейсов:**
- для претензии на маркетплейс обязателен номер заказа
- адрес владельца агрегатора подставляется из справочника автоматически
- в PDF-шапке строка «Номер заказа»
- UI: поле появляется только для маркетплейсов, placeholder — формат платформы

**Справочник маркетплейсов (реестр МЭР, 12 площадок):**
- modules/consumer/marketplaces.py: Ozon, Wildberries, Яндекс Маркет,
  Avito, Lamoda, Яндекс Еда/Go/Путешествия, Delivery Club,
  Магнит Маркет, Купер, Joom
- resolve_marketplace() в hardchecks/pre_checks/pdf
- Шапка PDF: «Владельцу агрегатора <entity> (<brand>)»
- Предупреждение pre-check: «Ответчик: <brand> — владелец агрегатора»

**Оговорка ст. 18 ЗоЗПП (15 дней):**
- defect + техсложный + >15 дней → предупреждение о существенности
  недостатка (продавец вправе предложить ремонт вместо возврата)
- <=15 дней → без предупреждения
- return14 не затрагивает

**Технически сложные товары (Постановление № 924):**
- холодильники, стиральные/посудомоечные машины, СВЧ, электроплиты,
  кондиционеры, компьютеры, ноутбуки, телефоны, телевизоры, мебель,
  электроинструмент
- для `return14` — стоп (нельзя вернуть надлежащего качества)
- для `defect` — ст. 18 работает, pre-check помечает «техсложный»

**Невозвратные товары (Постановление № 2463):**
- hard-check ловит категории, не подлежащие возврату за 14 дней:
  лекарства, предметы личной гигиены, парфюмерия, ткани, бельё,
  ювелирка, авто/мото, оружие, растения, книги, бытовая химия, пестициды
- Для `return14` — стоп с объяснением «нельзя, но вот что можно»
- Для `defect` — не блокирует, ст. 18 работает

**Особенности:**
- Авто-определение сценария через scenario_detect.py (regex)
- Умная шапка PDF: ООО/АО → «Директору», ИП/самозанятый → как есть,
  ФИО физлица → «Гражданину/Гражданке» (дательный, по полу), ники → «Продавцу»
- Физлицо-продавец: адрес ИЛИ ссылка на профиль (Авито, Telegram)
- Inline-валидация формы: ошибки под полями
- Нормализация телефона: +7 (XXX) XXX-XX-XX
- Whitelist норм (LLM не может выдумать статью)
- Pre-checks: критичны товар + суть проблемы + продавец + адрес продавца
- Gender detection для PDF (проживающий/проживающей, вынужден/вынуждена)
- Авто-скачивание PDF + редирект в карточку после submit
